# 精准报错工作流设计（方案 B：一键报告热键）

日期：2026-06-30
目标文件：`classroom_v4_3.html`（单文件 Three.js r164 空教室渲染）

## 背景与问题

本项目绝大多数「错误」是**画面视觉异常**——「截图里某个区域看起来不对劲」（太暗 / 太亮 / 颜色错 / 接缝 / 闪烁 / 缺失）。
这类问题用文字最难说清，因为收到一张截图时缺三样东西：

1. **复现**：哪个机位、什么时间预设——能否还原同一帧
2. **定位**：用户指的是哪一块
3. **症状/期望**：那块是什么物体、应该长什么样

文件已自带复现基建：URL hash 还原机位+预设（`#preset=noon&theta=…&phi=…&camR=…&panX/Z/Y`）、`P` 打印机位、无头渲染、`preserveDrawingBuffer:true`、合成截图函数 `takeShot()`、`DBG` 工具（`scene/camera/renderer` 已暴露、按 id 上色、`raycaster`/`ndc()` 已存在）。

## 方案

在现有 `DBG` 模块里加「报告模式」，默认关闭，不影响正式画面与无头渲染。

### 交互
- 按 `R` 切换报告模式；HUD/顶部提示「点一下出问题的地方（再按 R 取消）」。
- 在画面上点击异常处，自动：
  1. **射线拾取**命中 mesh，闪红高亮 ~0.7s 让用户确认选对。
  2. 生成**复现链接**（当前机位 + 当前预设打包成 URL hash）。
  3. 把**填好的 Markdown 报告**写入剪贴板（剪贴板不可用则打印到控制台）。
  4. 复用 `buildShotCanvas()` 存**截图**，并在点击处画**红圈**。
- 处理后自动退出报告模式，恢复正常 orbit/drag。

### 报告模板（除症状/期望两行全自动）
```
## 画面异常报告
- 复现链接: classroom_v4_3.html#preset=noon&theta=…&phi=…&camR=…&panX=…&panZ=…&panY=…
- 时间预设: noon
- 命中物体: <name>(#id, MaterialType)   // 未命中→「未命中物体(背景/窗/天空)」
- 命中点: 世界坐标(x,y,z) / 画面位置 NN%, NN%
- 截图: 报告_<时间戳>.png(问题点已红圈标出)

### 症状(填一句)
>

### 期望(填一句)
>
```

### 实现要点
- `takeShot()` 重构：抽出 `buildShotCanvas()` 返回合成画布（渲染层+辉光+颗粒），截图与报告共用，保证报告图与用户所见一致。
- 报告点击监听用**捕获阶段** `mousedown` + `stopPropagation`，避免误触发拖光/orbit。
- 当前预设从 `.preset-btn.on` 按钮的 `onclick` 解析；无则记为 `custom`。
- 高亮仅对含 `emissive` 的材质生效（守卫判断）。
- 顶部 toast 元素负责模式提示与「已复制/已保存」反馈。
- 同步更新 DBG 注释头与 HUD 键位行，加入 `R=报告`。

### 边界
- 点到窗外/空白未命中：仍记录机位+预设+画面位置百分比，物体栏标注「未命中」。
- 剪贴板 API 不可用（非 https/localhost）：报告打印到控制台，toast 提示按 F12 取。

## 我方闭环（收到报告后）
1. 用复现链接无头渲染同一帧 → 看到与用户一致画面。
2. 按物体名/id 定位代码，必要时 `DBG.id()` 上色交叉验证。
3. 修复。
4. 用**同一链接**再渲染，生成改前/改后对比图存 `docs/superpowers/compare/`。
5. 回复附前后对比，供用户验收。

## 不做（YAGNI）
拖框选区、症状下拉表单、自动像素 diff baseline（方案 C），维护成本高，暂不做。
